## 💡 什么是 OmniAtlas？

在 AI Agent 走向全场景落地的时代（无论是万行代码的复杂重构、企业财务报销的链条追溯，还是海量异构文档的语义检索），我们面临着共同的痛点：**上下文碎片化（Context Fragmentation）**、**长上下文遗忘（Lost in the Middle）** 以及 **文件盲目漫游带来的 Token 巨大浪费**。

**OmniAtlas** 是一套轻量级、开源的知识组织规范与工具集。它不绑定任何特定的开发平台，也不引入复杂的专有数据库，而是通过最基础的 **“Markdown 相对链接 + YAML 结构化元数据”**，将原本孤立的文件（代码、发票、资产凭证、业务文档）隐式地编织成一张高效的**全景知识网格（Knowledge Mesh）**。

它旨在作为人类与 AI 智能体之间的通用“世界语”，让小模型 Agent（如 8B/70B 级别）也能凭借一张轻量级的“高清地图”，秒级定位并流式消费复杂项目的任意局部。

---

## 🎯 核心设计目标

* **简洁直观，隐藏细节**：文档只做分层抽象与连接，将所有物理细节完整交回给源文件（如代码文件、原始单据）。
* **极致的 Token 友好度**：强制规范各层文档的 Token 与字数上限，支持面向小 LLM 模型的“逐步分块（Chunking）”消费。
* **高内聚的克隆即用**：整套元规范通过单个文件作为 Agent 的行为准则与专属 Skill，允许任何新项目克隆即用。
* **双向透明可视化**：让人类一眼看清数据流动与逻辑拓扑，让 Agent 的操作对人类完全可视化。

## 🗺️ 导航架构：渐进式缩放（Zoom Levels）

OmniAtlas 采用严密的逐层抽象设计，就像高精地图一样支持多级缩放：

* **`BLUEPRINT.md` (元规范)**：项目的全局标准与宪章。详细规定 L1、L2、L3 层次的文档规范、命名契约与连接规则。
* **L1 —— `AGENTS.md` (项目全景 - Root)**：项目的顶层设计、技术栈/业务大类、核心约束与推演原因。
* **L2 —— `[Module].md` (子域索引 - Sub-folder)**：以子文件夹命名的索引文档（如 `utils.md`, `finance.md`），说明该模块的设计思路，并通过标准链接向下嵌套，完美解决文档膨胀问题。
* **L3 —— 节点级详情 (具体文件/注释)**：深入物理文件底层。专用型实体（如深度学习自定义环境、特定财务报销函数）必须显式标明输入输出的 Shape、来源依赖与确切含义。

## 🛠️ 工程三剑客：如何消灭“文档漂移”？

为了确保这套系统在生产环境真正跑起来，OmniAtlas 围绕 CLI 工具集构建了三大核心机制：

1. **防止文档漂移的 Linter（自动化校验）**：轻量级静态检查工具，在 CI/CD 或 Agent 提交时运行，强制校验链接有效性及函数/实体签名的同步更新，彻底阻断错误文档误导 Agent。
2. **符号级精密锚定（Symbol-Level Anchoring）**：支持形如 `[用户鉴权](src/auth.py#class:AuthManager)` 的精密锚点协议，通过 AST（抽象语法树）实现跨文件的精准定位，免去通读文件的上下文消耗。
3. **增量更新协议（Incremental Update Protocol）**：利用 Markdown 注释标明原子区块（Block），允许 Agent 以只增（Append-only）或块替换（Block-replace）的方式无缝修改地图，防止小模型格式崩坏。
